# Connect workplace applications

Integrations connect Odella to the systems your team already uses. Once an application is connected, it can be assigned to specific workers or used in workflows, subject to the permissions and approval policies you configure.

## Browse integrations

Open **Integrations** from the Odella navigation. Search by application name or browse the available catalog. Each integration shows its name, purpose, and connection status.

Available applications vary by workspace and can include:

- Communication and productivity tools
- CRM and customer systems
- Document and file storage
- Finance and accounting systems
- Engineering and project-management tools
- Data, research, compliance, and business applications

## Connect a catalog application

<Steps>
  <Step title="Choose the application">
    Find the application in Integrations and start the connection flow.
  </Step>
  <Step title="Authenticate">
    Complete the supported sign-in method, such as OAuth or an API key. Review the requested permissions before approving access.
  </Step>
  <Step title="Confirm the connection">
    Verify that the integration shows as connected and that the intended account or workspace was selected.
  </Step>
  <Step title="Assign access">
    Add the integration only to the workers or workflows that require it.
  </Step>
  <Step title="Test safely">
    Run a read-only or low-risk test before enabling actions that send messages, change records, or delete data.
  </Step>
</Steps>

A workspace connection does not automatically give every worker access. Worker assignments, application permissions, outbound messaging rules, and tool approval policies remain separate controls.

## Governance checklist

Before using an integration in production, confirm:

- The correct organizational account is connected.
- Granted permissions are limited to what the process requires.
- Only appropriate workers can access the integration.
- Write, send, and destructive actions have suitable approval rules.
- A responsible owner knows how to revoke the connection.
- The workflow has been tested with representative data.

<Warning>
  Treat connected applications as access to real business systems. Use the narrowest permissions that still allow the worker to complete its responsibilities.
</Warning>

## Disconnect or change an account

Open the integration's connection settings to disable or reconnect it. Before disconnecting, identify workers, actions, and workflows that depend on the application. Those processes may stop working until a valid connection is restored.

If an expected integration is unavailable, contact [support@odella.ai](mailto:support@odella.ai) with the application name and intended use case.
