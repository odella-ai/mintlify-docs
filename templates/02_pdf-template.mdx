# Create a PDF template

PDF templates are best for forms and standardized documents where the page layout must remain fixed. Odella identifies fillable fields so you can review their purpose and define how each value should be populated.

## Before you begin

Use a current, approved PDF with existing form fields whenever possible. Confirm that:

- The file opens correctly.
- Field names are distinct and meaningful.
- Required and optional fields are known.
- Obsolete values and unresolved comments have been removed.
- You have authority to use the document as a template.

## Create the template

<Steps>
  <Step title="Upload the PDF">
    Open **Templates**, select **New Template**, and upload the source PDF.
  </Step>
  <Step title="Review template details">
    Give the template a specific name and description. Explain the document's purpose, when it applies, and how it differs from similar forms.
  </Step>
  <Step title="Review detected fields">
    Confirm that each expected field is present and correctly identified. Fix ambiguous field names or instructions before testing.
  </Step>
  <Step title="Add field instructions">
    Define the source, format, default behavior, and missing-data behavior for each field.
  </Step>
  <Step title="Test with representative data">
    Generate sample documents that cover normal, missing, long, and invalid values.
  </Step>
  <Step title="Publish">
    Publish only after the populated PDF has been compared with the approved source and reviewed by the process owner.
  </Step>
</Steps>

## Write field instructions

Good field instructions are specific and testable.

| Field type | Example instruction |
| --- | --- |
| **Name** | “Use the full legal name from the approved customer record. Preserve punctuation and suffixes.” |
| **Date** | “Use the agreement date in DD/MM/YYYY format. Do not substitute today's date when it is missing.” |
| **Currency** | “Use the approved contract value in AUD with two decimal places.” |
| **Checkbox** | “Select only when the source record explicitly confirms consent.” |
| **Signature** | “Leave blank for signing. Do not insert a typed name as a signature.” |

Avoid instructions such as “fill appropriately.” State where the value comes from and what to do when the source is unclear.

## Defaults and validation

Use defaults only for values approved to remain consistent across documents. Do not use defaults for facts that must come from the current matter, customer, transaction, or request.

Validation can include:

- Required-value checks
- Date and identifier formats
- Allowed value lists
- Number and length limits
- Cross-field consistency checks

## Test the output

Include tests for:

- Every required field
- Missing optional fields
- Long names and addresses
- Special characters
- Multi-line text
- Each checkbox and dropdown state
- Values near field-length limits
- Page rendering and print output

## Assign and use the template

After publishing, assign the PDF template to the appropriate workers or select it in a [Populate Template block](/block-reference/draft/populate-template). See [Use templates](/templates/04_using-templates) for delegation and review guidance.

<Warning>
  Review generated PDFs before filing, signing, sending, or relying on them. A populated form can still contain incorrect source data or an inappropriate template choice.
</Warning>
