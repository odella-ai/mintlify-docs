# Create consistent documents from approved templates

Templates turn repeatable PDFs and Word documents into reusable drafting resources. Workers and workflows can use them to create documents from structured data, source files, messages, and connected applications.

## When to use a template

Use a template when the output must follow an established structure, layout, or precedent.

<CardGroup cols={2}>
  <Card title="PDF templates" icon="file-pdf" href="/templates/02_pdf-template">

## Template lifecycle

<Steps>
  <Step title="Choose an approved source document">
    Begin with the version your team is authorized to use. Remove obsolete content and unresolved comments before upload.
  </Step>
  <Step title="Create the template">
    Upload a supported PDF or DOCX file, then review the generated name and description.
  </Step>
  <Step title="Configure fields and instructions">
    Define how source values map into the document and explain when the template should be selected.
  </Step>
  <Step title="Test representative data">
    Include missing optional values, long text, special characters, and each conditional path.
  </Step>
  <Step title="Publish">
    Publish only after the output has been reviewed against the source document.
  </Step>
  <Step title="Assign and govern">
    Add the template only to workers and workflows that need it. Review it again whenever the underlying precedent changes.
  </Step>
</Steps>

1. Upload a PDF or DOCX source document.
2. Review the proposed name and description.
3. Create the template and open its editor.
4. Add clear usage instructions.
5. Test the generated document before publishing.

## Write useful template instructions

Instructions help a worker decide when and how to use the template. Include:

- The document's purpose
- When to use it and when not to use it
- Required source information
- Field-mapping and formatting rules
- Optional sections and conditional behavior
- Escalation requirements for missing or conflicting data
- The person responsible for reviewing the result

<Tip>
  Distinguish similar templates explicitly. For example, explain which jurisdiction, customer type, transaction, or process each template applies to.
</Tip>

## Draft and published states

Use **Save** while configuring and testing. Publish the template when it is ready to be used by assigned workers and workflows. A saved draft should not be treated as production-ready.

## Use templates with workers

A worker can select an assigned template when the delegated task and template instructions match. It gathers source information, populates the document, and returns the result for review.

See [Using templates](/templates/04_using-templates) for delegation and review guidance.

## Governance checklist

Before publishing, confirm:

- The source document is current and approved.
- Every required field has a defined source.
- Optional and missing values are handled safely.
- Dates, numbers, names, and currencies use the required format.
- Conditional sections have been tested.
- Generated output preserves the required layout.
- A human reviewer is identified for business-critical documents.

<Warning>
  Templates improve consistency but do not validate the legal, financial, regulatory, or operational suitability of generated content. Apply the review required by your organization.
</Warning>
