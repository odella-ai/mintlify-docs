## How Workflows Fit Into Odella

Workflows are like digital roadmaps. They guide AI employees through tasks from start to finish, ensuring the right information is gathered, the right logic is applied, and the right output is produced.

Each AI employee can use:

- **Ready-made workflows** for common tasks
- **Custom workflows** designed around your organization's process
- **Templates** for document generation
- **Documents and knowledge bases** for context and precedent
- **Integrations** for connected tools and systems — see [Integrations Overview](/integrations/overview)

The page provides:

- **Search workflows** — find a workflow by name.
- **Sort** — reorder the list.
- **New Workflow** — opens the Create Workflow wizard (see below).

Each workflow appears as a card showing its icon, name, node count (e.g., "12 nodes"), and a short description. Cards that run on a schedule or event also show a **Trigger active** label, and connected integrations appear as small app icons along the bottom (e.g., Slack, calendar, BigQuery). A per-card menu (⋮) opens actions for that workflow. A workflow with no steps yet shows "0 nodes," and one without a description shows "No description available."

Click **New Workflow** to open the Create Workflow wizard.

<Steps>
  <Step title="Choose How to Start">
    "How would you like to start your workflow?" Select one of three options and click **Next**:

    - **Start Blank** — create a new workflow from scratch with a clean canvas.

## The Workflow Canvas

The canvas is the visual builder where the process is assembled.

- **The canvas** (right) is the working area where blocks are placed and connected. Flows are organized into tabs, starting with **Main Flow**.
- **The Assistant panel** (left) helps you build by describing what you want — "How can I help? Tell me about your idea, and I'll help you build it." This is the conversational way to assemble or modify a flow.
- **Canvas controls** along the top include a refresh/reset control, a panel-collapse toggle, and a settings gear for the workflow.

From here, follow the remaining build steps — design the process by adding and arranging blocks, configure and connect each block's inputs and outputs, test and debug the run, then save and publish the workflow to the AI employees that should use it. See [Working with Flows](/workflow/working-with-flows), [Workflow Interface](/workflow/interface), and [Blocks](/workflow/blocks) for detail on each.
