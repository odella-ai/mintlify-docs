---
title: "Chat with an AI Employee"
description: "Start a conversation, share source material, answer questions, and review work without starting from a task board."
---

Start by talking to your AI Employee about the outcome you need. You can ask a question, work through an idea, or delegate a piece of work in the conversation. You do not need to create a task on the board first.

## Start a chat

1. Open **Workforce** and select the intended AI Employee.
2. Select **Chat** where available. Check the worker's name before sharing information.
3. Write your request in the message composer. Attach relevant source files where offered, and wait for uploads to finish.
4. Send the message and follow the reply. Answer clarification questions in the same conversation.

The **Chat** control depends on a published web channel and your access. If it is missing or unavailable, ask the worker's manager to check [channel setup](/workforce/channels/web-chat), availability, and permissions. Opening a chat does not itself make a paused worker available.

## Give a clear brief

Describe the **outcome**, **source material**, **constraints**, and **review criteria**. For example:

> Review the attached supplier proposal. Return a one-page summary of cost, delivery dates, missing details, and questions for me. Cite the source for each finding. Do not contact the supplier or change external records.

You can refine the request with follow-up messages: “Separate confirmed delivery dates from estimates,” or “Show the source for the renewal clause.” Keep corrections with the relevant conversation rather than starting duplicate work.

Instructions guide the worker; configure actual [access and action policies](/guides/access-and-security) separately. Do not send passwords, API keys, recovery codes, or one-time codes in chat. Use [Vault or a browser handoff](/workforce/computer) when credentials are needed.

## Follow work from the conversation

Some requests can be answered directly; others lead to delegated work with its own progress and result. **Accepted is not completed.**

- Read progress updates and respond to questions where requested.
- If an action needs authorization, inspect its [approval card](/workforce/approvals). A typed “yes” is not a substitute for the displayed approval control.
- If the worker needs you to sign in, complete MFA, or answer a CAPTCHA, use the [browser handoff](/workforce/computer), then return to the conversation.
- Use [Tasks](/workforce/tasks) when you need to inspect delegated work, status, or a blocker. Do not resubmit just because an update is slow.

## Review the answer and files

Read the actual deliverable, not just the worker's completion message. Check sources, calculations, missing information, and whether the result meets your brief.

Open or download returned files using the controls offered. Supported documents can open beside the conversation; select a later revision explicitly rather than assuming an existing preview has updated. See [document review](/workforce/talk#review-returned-documents).

Give corrections in the conversation. If the same correction should apply to future work, ask an authorized editor to update the worker's instructions or skills.

## Choose another way to talk

- **Workplace messages or email:** [Contact an employee through channels](/workforce/contact-an-employee).
- **Voice in the current browser chat:** [Talk and document review](/workforce/talk).
- **A separate tracked assignment:** [Assign and track tasks](/workforce/tasks).

Channel availability, attachments, voice, and approval controls vary. Switching channels should not be assumed to carry over the full conversation or an open document preview; include the relevant context and check which work you are continuing.
