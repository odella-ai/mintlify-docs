# Talk to an AI Employee

Where **Talk** is available in your chat, use it to speak with a worker in the current conversation. Browser Talk is separate from a [Phone channel](/workforce/channels/phone-and-messaging) or meeting participation.

<Note>
  Voice availability depends on your account, worker setup, and current feature
  availability. Use the controls shown in your account; do not assume every
  channel or browser offers the same voice capabilities.
</Note>

## Start and finish a conversation

1. Open a chat with the intended AI Employee.
2. Select **Talk** and allow microphone access when the browser asks.
3. Wait for the connection state before speaking. Use the displayed microphone/mute control when needed.
4. Delegate a concrete outcome, including source material and any review requirements.
5. Select **End** to return to messages when finished.

If microphone access is denied, check the browser's site permissions and selected input device. Use headphones if audio feeds back through your microphone. Avoid starting multiple voice sessions in different tabs while troubleshooting.

## Follow work started during Talk

The worker may accept a task and continue the work separately from the conversation. **Accepted is not completed.** Use the task progress and details to check questions, approvals, failures, and deliverables.

You can provide text guidance through the available composer. Do not assume a spoken “yes” replaces a required [approval](/workforce/approvals).

## Review returned documents

When a task returns an actual file, use **Open** or **Download** where offered:

- Supported documents and Markdown can open in the conversation's document canvas.
- Unsupported preview formats may still be downloadable.
- Opening or closing a preview does not itself end the conversation.
- If a later revision arrives, select it explicitly rather than assuming an open preview has been replaced.

Ending Talk returns to messages and can leave the current preview open. Task results are associated with the originating work; check the task if a result is not immediately visible in the chat.

## Attachments and document context

Use normal text-chat uploads or task attachments to supply source files. The current Talk flow does not offer general voice attachment submission; it can retain drafts or attachments that must be handled in text chat instead.

An open preview is not proof that all of its content has automatically been shared with the worker. Name the document and intended revision in your request, and confirm the relevant source is attached or accessible.

## Recover from a problem

| Problem                             | Next step                                                                                               |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Voice cannot connect**            | Check microphone permissions, connection state, worker availability, and account eligibility.           |
| **Task updates disconnect**         | Retry task updates or open Tasks; do not create duplicate work just because the progress view is stale. |
| **Preview fails**                   | Retry the preview or download the returned file. Check the task independently.                          |
| **A task is waiting**               | Open details and answer the question or resolve its approval.                                           |
| **Call ended before work finished** | Check the task's current status rather than assuming it was cancelled.                                  |
