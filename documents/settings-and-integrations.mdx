Open a Document Store's **Settings** to maintain its configuration. The available tabs depend on the store type and your permissions.

## Settings areas

| Tab              | Purpose                                                                             |
| ---------------- | ----------------------------------------------------------------------------------- |
| **General**      | Name, subtitle, and description; signing-store lifecycle controls where applicable. |
| **Columns**      | Metadata fields extracted from documents in a standard store.                       |
| **AI Model**     | Model used for metadata extraction.                                                 |
| **Sync Sources** | Connected Google Drive or OneDrive folders.                                         |
| **Access**       | Resource sharing in an organization account.                                        |
| **Storage**      | Explains the store's purpose and record restrictions.                               |
| **Delete**       | Permanent deletion for eligible standard stores.                                    |

Signing-record stores expose **General**, **Access**, and **Storage**, not the normal ingestion, extraction, or deletion tabs.

## General settings

Use a specific name, subtitle, and description so people and AI Employees understand what belongs in the store. Editing a description does not replace reviewing the files themselves.

## Change metadata columns

In **Columns**, update the fields and their extraction descriptions. When saving changed columns, choose how existing documents should be handled:

| Choice                      | Effect                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------- |
| **New files only**          | Apply the columns to documents uploaded after saving. Existing files remain as they are. |
| **Fill existing files too** | Re-run extraction on existing documents for added or changed columns. Billed per page.   |
| **Rename labels only**      | Change column names without reprocessing documents.                                      |

For example, add **Renewal owner** with **New files only** if you only need it for future uploads. Choose **Fill existing files too** if your existing contract library also needs that information, and review the processing estimate before confirming.

<Warning>
  Reprocessing can consume credits and take time on large stores. Renaming a
  label is not the same as asking AI to extract a different business value.
</Warning>

## Sync sources

Connect a **Google Drive** or **OneDrive** folder for ongoing imports. Configure:

- **Connection Name** and **Description** to identify the source.
- **Include subfolders** if nested folders belong in this store.
- **Sync existing files** to import files already in the selected folder.

After creating a connection, you can pause, resume, or delete it. Check the correct provider account and folder before enabling a source. A connection does not grant every worker access to its contents.

If imports stop, check the provider connection, folder permissions, and document processing status before reconnecting or retrying. Use manual upload for one-off files instead of an ongoing folder connection.

## AI model

Choose a model appropriate for the complexity and sensitivity of your documents. The selector may show the resolved model and estimated cost per 1,000 pages. Review extracted values against source documents before relying on them.

## Access

In an organization account, use **Access** to review and change who can use the store. You need the appropriate resource-management permission to change sharing. Worker assignment and your organization's access rules remain separate controls.

For signing stores, access changes affect **past records as well as future records**. Review the audience before sharing sensitive executed documents. See [Roles and permissions](/platform/roles-and-permissions).

## Storage and store types

**Storage** explains what the store holds and which operations are permitted. It does not configure automatic retention or deletion.

| Standard Document Store                                                                                         | Signing-record store                                                                                                |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Documents and extracted metadata for search and retrieval.                                                      | Signed PDFs, completion certificates, audit trails, and signing evidence.                                           |
| Upload, sync, metadata editing, reprocessing, and deletion are subject to permissions and document protections. | No manual uploads, sync imports, AI indexing, editing, replacement, reprocessing, or deletion of protected records. |
| Ordinary document lifecycle.                                                                                    | Archive/restore lifecycle for accepting new signing requests.                                                       |

Some synced files may contain extracted text without a retained original. Their preview indicates when the original is not stored.

Create or select a signing store while configuring [E-signing](/templates/05_e-signing). The store type is fixed when created.

- **Archive** stops new signing requests from using the store.
- Requests already sent can still be completed, and existing records remain available.
- **Restore** allows new requests again.
- Archiving is not deletion, and the Storage page does not set a disposal date.

Record disposal, where required, needs a separate approved process. Do not use ordinary Document Store deletion instructions for signing records.

## Delete a standard store

Use **Delete** only for an eligible standard store. Review its documents, connected workers, workflows, and sync sources first. Export metadata and download files you must preserve.

<Warning>
  Deleting a standard store permanently removes its documents, metadata, and
  search data. Protected signing stores do not offer this operation.
</Warning>

## Use stores with your workforce

Assign a store as [Knowledge](/workforce/knowledge) only to workers that need it. Workflows can search and analyze stores as part of approved processes.

Use [Workspace](/workforce/workspace) for task files and drafts; use a standard Document Store for reusable source material; use a signing store for protected completed signing records.
